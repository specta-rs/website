This guide is for an existing application using rspc 0.3.0. rspc is no longer maintained. Do not mix these dependencies with the experimental procedure API.

## Create a project

```bash
cargo new rspc-example
cd rspc-example
cargo add rspc@=0.3.0 rspc-axum@=0.2.0 axum@0.7
cargo add tokio --features macros,rt-multi-thread,net
```

If you add Specta directly for custom payload derives, use the `2.0.0-rc.20` release required by rspc 0.3.0, not the version in the current Specta guide.

## Define and expose a router

```rust copy filename="src/main.rs"
use rspc::{Config, Router};

fn router() -> Router<()> {
    Router::new()
        .config(Config::new().export_ts_bindings("./bindings.ts"))
        .query("version", |t| {
            t(|_: (), _: ()| env!("CARGO_PKG_VERSION"))
        })
        .build()
}

#[tokio::main]
async fn main() {
    let app = axum::Router::new()
        .nest("/rspc", rspc_axum::endpoint(router().arced(), || ()));

    let listener = tokio::net::TcpListener::bind("127.0.0.1:4000")
        .await
        .expect("failed to bind server");
    axum::serve(listener, app).await.expect("server failed");
}

#[cfg(test)]
mod tests {
    #[test]
    fn router_builds() {
        super::router();
    }
}
```

Run `cargo run` to export `bindings.ts` and start the server. Binding export through `Config` happens only in debug builds. Run the router test in CI before building the frontend.

## Create a frontend client

```bash
npm install @rspc/client@0.3.1
```

Copy or export the bindings into your frontend source directory:

```typescript copy filename="src/api.ts"
import { createClient, FetchTransport } from "@rspc/client";
import type { Procedures } from "./bindings";

export const client = createClient<Procedures>({
  transport: new FetchTransport("/rspc"),
});

console.log(await client.query(["version"]));
```

Proxy the same-origin `/rspc` path to the Rust server during development. For a cross-origin API, use its full URL and configure CORS in Axum.
